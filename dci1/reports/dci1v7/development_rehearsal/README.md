## Starting a rehearsal on the corrected tree

A rehearsal under the corrected code goes into a **fresh root** — the next
free number, never an existing one — because a development tree's records
are write-once and the lifecycle refuses a stage that already has one:

```
cd dci1
DCI1_V7_DEV_ROOT=evidence/dci1v7-development-r5 \
    tools/run_v7_replication.sh <model_key> <device> <log_dir>
```

Two lanes per card (one model each), the backend's per-device lock as the
arbiter, `DCI1_V7_CPU_WORKERS` inherited by every stage. The Gate-2 record of
a corrected rehearsal carries `chance_basis` (the unconstrained cells the
column was measured on), `calibration_rows_withheld` (any candidate whose
chance reached `CHANCE_DEGENERACY_MAX`, with its values) and a non-zero
`chance_compliance` wherever the model satisfies a candidate unprompted; a
Gate-2 record without `chance_basis` was produced by the pre-correction code.

**Comparability.** A corrected rehearsal and a zero-column rehearsal of the
same model are two different calibration procedures and are not compared
number for number; the impact report is the bridge, and it is computed from
the stored zero-column rows rather than from a new run.
