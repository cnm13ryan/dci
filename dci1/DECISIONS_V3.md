# DCI-1 v3 — registered implementation decisions

Registration-manifest values and executable readings fixed **before any v3
artifact exists** (all dated 2026-08-17, pre-registration of the study
tree). The sole scientific authority is
`user-notes/DCI-1_preregistration_v3.md`; the anti-regression specification
is `user-notes/DCI-1_v2-to-v3_changelog.md`. Nothing below alters a
registered scientific rule; each entry either fixes a manifest value the
preregistration delegates to registration, or records the executable
reading of a construction the preregistration describes in prose.

| V20 | Gate 1 reviewer interface (workflow tooling, no scientific rule): `dci1v3/annotation/` serves one blinded annotator session per (model, annotator) over the registered packet. Annotator payloads carry only constraint text, response text, and the annotator's own saved work — item identities, verifier verdicts, class structure, sampling status, and other annotators' labels are structurally absent; display order is a per-annotator seeded shuffle (`dci1v3:annotation:v1`) so the packet's class-ordered layout cannot leak; no occurrence highlighting or counting exists in the interface. The §25 instruments are `annotation/rubric.py` v1.0.0: written instructions and twelve worked examples demonstrating the plain reading on clear cases only. Labels use the registered binary vocabulary (SATISFIES→pass, VIOLATES→fail); a flag is workflow metadata and never exports; finalisation requires a binary label on every item plus the §10 face-validity judgment and is immutable thereafter. Export produces exactly the `gate1 --annotations` file ({item_id: [3 labels], face_validity: [3 bools]}, annotators in sorted order) and exists only once all three sessions are finalised; researcher agreement/verifier diagnostics stay hidden until then. Session files record true item id, annotator id, label, sequence, timestamp, flag, rubric and interface versions for audit, outside the evidence tree (`dci1/annotations/`, gitignored) until submitted through the registered Gate 1 pathway. | §10, §25; workflow only |
