## 2. Model profile, execution mode, and configuration

Three model roles, each with a verified immutable revision. `main` is never a
scientific revision.

| profile | model | role | produces evidence |
| --- | --- | --- | --- |
| `dev_fast` | Qwen2.5-0.5B-Instruct | engineering: batching, tokenizer, persistence, resume | no — `DEVELOPMENT_ONLY` |
| `pilot` | Qwen2.5-1.5B-Instruct | feasibility: dynamic range, runtime, output pathologies | no — `PILOT_MODEL_SPECIFIC` |
| `study` | Qwen2.5-3B-Instruct | the scientific target | yes |

The profile enters the execution fingerprint **and** the directory tree, so a
cache written under one profile can never be read under another. Behavioural
results never transfer between profiles; every empirical gate is rerun from
scratch when the profile changes.

Fields listed in `PROTOCOL_FIELDS` at the freeze cell determine the protocol
hash. Operational fields (paths, mirroring, telemetry, hardware) are recorded
separately and do not.
