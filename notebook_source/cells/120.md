## 3. Environment, run identity, statuses, and gates

Every scientifically distinct failure gets its own machine-readable status and
its own artifact. A gate record always states what happened, which quantity
caused it, against which threshold, whether more calibration data could resolve
it, and whether repairing it requires a new protocol version. Those last two
fields are the difference between "collect more" and "stop and redesign".

Run directories live under Drive, keyed by protocol version, model profile and
run id, and are never overwritten. A run with no `RUN_ID` resumes the most
recent run whose execution fingerprint matches, and otherwise starts a new one.
